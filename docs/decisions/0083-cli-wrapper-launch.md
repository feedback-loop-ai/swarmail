## Authority and purpose

The checksum-verified 2026-10-26 operator direction requires launching wrappers
using selected existing logins, measured restrictions and honest per-family
tool-surface disclosure. The linked spec records the exact packet digests and
reconciles both panel positions. This proposal records the new private-input
and public metadata contracts; it does not re-litigate the direction or accept
itself. It changes no frozen guarantee or mail behavior.

## Proposed ruling

1. Three fixed recipes in the existing eval executable launch the six approved
   models without retries, substitution, effort overrides or goal rewriting.
   Configuration admits only fixed closed versioned selections and measured
   exclusion mechanisms. Unexcludable managed sources cause prelaunch refusal;
   tool asymmetry does not. No provider call belongs to delivery proof.
2. One explicitly selected owner-only file per family supplies its existing
   login. Claude projects a minimal inference-scope OAuth record; Codex projects
   ChatGPT id/access/account tokens with an inert refresh placeholder; dsh
   exports only the selected route key. Bound descriptor-validated reads and
   private-before-payload files under trial HOME replace ambient inheritance.
   Never copy login directories, rotate source credentials or publish secrets.
3. Current schema-2 rows require a closed canonical descriptor at
   provenance.agent.tool_surface. It names declared configuration, evidence
   revision, restrictions and conservative residual access. Builtin, unknown
   external and invalid-request descriptors are explicit. Include setup failures
   and never-started rows without claiming execution. Assigned contexts,
   retention/replay and baseline accounting validate the same descriptor.
4. Reject older rows lacking that descriptor, malformed profiles and conflicting
   declarations. Keep catalogue/snapshot/result versions 2 and existing envelope
   versions, score precedence and report formulas. Historical evidence needs
   its historical binary. Reports retain profile differences and explicitly
   state tool asymmetry; no opaque profile-only or inferred two-tools claim.
5. Null raw CLI stdout/stderr at launch. Give the fixture helper a separately
   cleared environment through an exec boundary inside the existing executable.
   Keep CLI/helper descendants in the runner's registered group. Only the
   existing owner controls deadline, termination, reaping, private-state disposal
   and admission release. Actual cessation, not leader exit, precedes scoring.
6. Versioned help/config and nearby-version live measurements justify assembly
   only. Authenticated six-model smoke, exact-version interoperability and live
   dsh HTTP MCP are operator-owned outstanding proof. All rows stay unconfined;
   same-uid hostility, escaped sessions and crash-proof cleanup are not promised.

## Alternatives and costs

Adopt simplicity's fixed builders, closed JSON and exec; reject a platform,
dotenv grammar, refresh subsystem and second supervisor. Cost: reviewed recipe
updates, operator credential preparation/renewal and dependency on the existing
cleanup owner. Adopt robustness's explicit Claude tool names and effective
helper environment boundary. Cost: catalogue parity maintenance and another
small dispatch/proof path. Choose simplicity's strict new reader over the
optional old-row fallback robustness allowed. Cost: historical-binary access
for older rows. Adopt both panels' typed disclosure and residual honesty; native
Codex/dsh tools remain a confounder that reports must show.

## The Spark cell

glm-spark × `digest-lookalike` first ran 0/5, all `gave_up`. That is not a
model result. The model server on the Spark box (tensorfold, serving
`GLM-5.3-Flash-EXL3` on `spark:8888`) stopped answering during the cell:

- glm-spark passed `recipient-crowd` 5/5 at 18:17, so the server was up;
- the cell's first trial ran 318 s; the other four exited with status 1 after
  about 17 s, having made no request of the application;
- afterwards nothing listened on `spark:8888`, and a one-trial control on
  `recipient-crowd`, which the model had just passed, failed the same way.

After the operator restarted the server, a fresh control passed, and the cell
was rerun: 5/5 pass, server still up afterwards. The scored table and
`report.json` use the rerun. `paid.jsonl` keeps the original five rows.
Whether the long first trial took the server down cannot be told from the
harness side.

The wrappers cannot tell a dead model server from a model that gives up: both
land in `gave_up` with no app events. A harness check that names an
unreachable provider, perhaps as a `harness_error`, would have kept these
rows out of the model's column. It is not built.

## What this means

#309 asked for a tier "that current models fail some of the time", to give
#151's failure taxonomy something to rank by. At five trials per cell it
produced one failure in 75. That is the same rate as the default tier
(5 in 400 is 1.25%; 1 in 75 is 1.3%). The traps were real to the oracle and
null controls but did not trip these models. Choosing what comes next is the
operator's call:

1. **Harder still.** Tighter budgets (deadlines, turns, tokens), several
   inboxes per agent, or traps that need state across mails rather than one
   careful read.
2. **More trials, not harder tasks.** At 1–2% failure rates, ranking needs
   hundreds of trials per model to separate anything.
3. **Accept saturation.** Treat the suite as a regression gate and stop
   trying to steer the epic by its failure taxonomy.

This record does not edit #309, #151 or #163.

# v0.1.0 — the fast, AI-native mail mock

First release. One Rust binary: lossless SMTP capture + REST/MCP/UI.

## Guarantees (asserted in CI)

- **5000/5000 exact** over 100 concurrent fresh SMTP sessions — zero loss
  (`tests/rate.rs`, the Kratos-courier pattern that killed MailSlurper).
  *Correction (2026-10-18, issue #104):* when v0.1.0 was tagged, this proof
  did not gate publication. The tag-only `release-rate-5k` job is now a
  `needs:` of both publish jobs, so a later tag that fails it does not
  publish.
- **Ingest path: 1.28 µs/mail** parse+extract, **1.58 µs** with insert
  (criterion medians → ~630k mails/s/core).
  *Correction (2026-10-19, issue #142):* the heading's "asserted in CI"
  covers only the 5000/5000 proof above, and only on tag refs (the
  `release-rate-5k` job). These medians are a dated local `cargo bench`
  measurement: no CI job runs `cargo bench`, and nothing gates on them.

## Agent layer

- MCP over HTTP (`POST /mcp`) and stdio (`swarmail mcp`) — 12 tools incl.
  `swarmail_wait_for_email` (push-based, no polling),
  `swarmail_extract_links`/`codes`, `swarmail_seed_email`,
  `swarmail_set_chaos`.
- `/openapi.json` (3.1) + `/llms.txt` served from the binary.

## Test layer

- `GET /api/v1/inboxes/{inbox}/await` — long-poll until N matching mails
  arrive (subscribes before it checks — decision 0002).
- Per-test inboxes: SMTP AUTH username names the inbox (decision 0004).
- Chaos: connect/mail_from/rcpt/data rules (probability + SMTP error +
  delay) — 97.8% covered.
- Webhooks: queued, retried (100ms→1.6s), inbox-filtered,
  `X-Swarmail-Secret`.
- Seed endpoint: synthetic fixtures through the full parse/extract
  pipeline.
- Embedded UI, Prometheus `/metrics`, `/healthz`.

## Try it

```bash
docker run -p 1025:1025 -p 1110:1110 -p 8025:8025 ghcr.io/feedback-loop-ai/swarmail:main
# or, from a checkout (the crate is not on crates.io)
cargo install --locked --path . && swarmail serve
```

*Correction (2026-10-18, issue #103):* these lines originally named
`swarmail:v0.1.0`, which was never published, and `cargo install
swarmail`, which is not on crates.io. `:main` is mutable; see the README
for reproducible tags and the checkout-based Helm install.

*Correction (2026-10-19, issues #141, #142):* run the image as
`docker run --rm --stop-timeout 30 …`. Without `--rm` every run leaves the
image's anonymous `/data` volume behind; and `docker stop`'s default 10 s
grace before SIGKILL equals the server's 10 s drain, so a draining stop
can be killed at the knife's edge (decision 0027 §8). The command above is
kept as it was corrected on 2026-10-18; the README carries the current
quickstart.

## Known v0.1 limits

`http://` webhook targets only, no STARTTLS yet, in-memory storage. See
the README roadmap. Line coverage 59.9%; the hot paths that carry the
losslessness guarantee are the covered ones (per-module table in the
README).

*Correction (2026-10-19, issue #142):* the README no longer carries a
per-module coverage table. The gate has since become exact — 100% of
lines, branches and functions, reports under `target/coverage/` — so the
59.9% figure describes only the v0.1.0 artifact.

## Unreleased — extraction fidelity (2026-10-18)

Not part of the original v0.1.0 artifact; recorded here until the next
release cut. Issues #74, #93, #94; decision 0040 (proposed).

- A multipart/mixed mail keeps its genuine text *and* html bodies, in
  either order; attachments and attached messages are still not bodies.
- HTML codes come from the html's own text runs: adjacent cells and blocks
  are never joined into one number, typed `<style>`/`<script>`, `<head>`,
  `<template>`, `<title>`, comments and attribute values yield none, and
  only ASCII digits are codes.
- HTML links are cut after entity decoding, so `&lt;url&gt;`,
  `&quot;url&quot;` and `&nbsp;` end the link; the scheme matches
  case-insensitively.
- **Known limit:** data files written before this change keep their old
  derived fields (`text`, `html`, `links`, `codes`) forever — restore is
  verbatim and nothing re-derives them; a restart does not repair them.
  The named-entity table shipped here was an interim subset; the full
  WHATWG set is imported under "extraction and compat" below (decision
  0040 §5, §7; 0049 §2).

## Unreleased — webhook boundary (2026-10-18)

Not part of the original v0.1.0 artifact; recorded here until the next
release cut. Issues #75, #76, #97, #98; decision 0041 (proposed).

- A webhook secret must be a header value the delivery client accepts:
  U+0001, DEL and every other control but tab are refused at PUT, as are
  leading or trailing spaces and tabs — previously such a secret was
  accepted and then failed every delivery. Padded secrets that used to be
  accepted are now a 400.
- Deliveries ignore `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY`: the
  configured address is dialed directly, so no proxy receives the payload
  or the secret.
- URL userinfo is stripped from GET and PUT echoes and from every log line
  (the delivery still sends it as Basic authorization). Query strings are
  still shown — keep credentials out of them.
- A mail's payload is serialized once and shared by every target and
  retry, instead of copied per attempt.
- The shutdown sweep keeps counting past a lagged firehose, and a graceful
  stop logs one `webhook dispatcher stopped` line with the five final
  totals — the shutdown `aborted` count was never visible on `/metrics`.
- Over-budget refusals are all counted, but each target warns at most once
  per 60 s.

## Unreleased — extraction and compat (2026-10-18)

Not part of the original v0.1.0 artifact; recorded here until the next
release cut. Issues #136, #137, #138, #139; decision 0049 (proposed).

- A quoted attribute's link ends at the attribute's own closing quote and
  is decoded after: `href="…?name=O&#39;Brien&amp;token=…"` (and the
  `&#x27;` and `&quot;` forms) keeps its token. Balanced parentheses, IPv6
  brackets and interior commas stay in a link; trailing sentence
  punctuation and unmatched closers are trimmed. `&#+52;` and other signed
  or non-ASCII numeric references stay literal.
- Text-part codes are preferred only when the text and HTML parts are
  direct siblings in one `multipart/alternative`; otherwise both bodies
  contribute in source order, so a list footer or an inline text file after
  an HTML-only mail no longer hides its code.
- A fresh mail keeps at most the first 64 distinct codes; the same capped
  array is stored, served and sent to webhooks. Rows stored earlier keep
  their arrays verbatim. Links remain uncapped.
- Mailpit's `-to:x`, `!from:x`, `"to:x"`, `-"subject:x"` and `(to:x)` are a
  named 400 on both containing searches instead of a vacuous zero. Every
  compat list and search, scoped or global, and `latest` share one order —
  receive time, then id; `latest?tz=` stays a named 400, now documented.
- Single-message responses (Mailpit full/plain/raw/headers, the three
  `latest` routes, MailHog download, native `GET /api/v1/messages/{id}` and
  `/raw`) are built on the blocking pool.
- Every one of the WHATWG's 2,125 semicolon-ended named character
  references now decodes in HTML links — `caf&eacute;` is `café`,
  `go&rarr;` is `go→` — generated from a pinned, unmodified snapshot of
  `entities.json` (fetched 2026-10-18, SHA-256 `d741d877…62e6`, CC-BY-4.0,
  shipped as `scripts/data/html-entities.json`) and tested against every
  mapping in it. The 106 legacy names without a semicolon (`&amp`,
  `&eacute`) stay literal by design (decision 0040 §5, 0049 §2).

## Unreleased — compat and validation sweep (2026-10-18, recorded 2026-10-19)

Not part of the original v0.1.0 artifact; recorded here until the next
release cut. Landed in `582c73a` (#118; issues #91, #95, #96, #99, #100;
decision 0044) without an entry of its own — this one is added late
(issue #142). Client-visible changes:

- **Unknown query keys are a 400.** From #118 the native list
  (`GET /api/v1/inboxes/{inbox}/messages`), `await`, `assert`, `count` and
  the inbox listing, and the Mailpit `latest` routes, refuse a query key
  their shape does not have instead of dropping it. Batch 3 (`067ab91`,
  #134) later closed each native shape to its own keys — `count?limit=`,
  `assert?timeout_ms=`, and any key on threads and feed now refuse too.
  The Mailpit/MailHog **list and search** shims keep upstream's tolerance
  of unknown keys (`/api/v1/messages?inbx=` answers the whole store).
  Proof: `tests/api.rs::an_unknown_native_query_key_refuses_by_name`,
  `tests/compat.rs::latest_refuses_a_query_an_unknown_key_and_a_blank_inbox`.
- **Renamed key:** the Mailpit list and search envelopes'
  `messages_unread_count` is now `messages_unread`, upstream's own key
  (swarmail keeps no read state, so it counts every listed or matched
  mail). Proof:
  `tests/compat.rs::mailpit_envelope_lists_the_store_newest_first`.
- **The shims' sender is the envelope.** MailHog `From`, `Raw.From` and
  `kind=from`, and Mailpit `ReturnPath`, now report the stored SMTP
  `MAIL FROM` (`""`/`<>` for a bounce) instead of the header `From`; only
  mail stored before the envelope was kept falls back to the header.
  Mailpit's `From` and the native `from` filter stay on the header. Data
  files gain an envelope column on first open. Proof:
  `tests/compat.rs::the_compat_sender_follows_the_envelope`.
- **Large MailHog pages refuse.** A MailHog v2 list or search page whose
  JSON would pass 64 MiB (67,108,864 bytes) is refused whole with a 400
  (`compat page exceeds byte budget 67108864; reduce limit or fetch raw by
  id`) instead of being built. Proof:
  `tests/compat.rs::an_over_budget_mailhog_page_refuses_by_name`.
- Also in #118: `latest` serves `/raw` and `/headers`, and a nonblank
  `?query=` on it is a 400 (see the 582c73a correction below); MCP answers
  a non-object member `-32600`, invalid UTF-8 `-32700` and an oversized body
  a JSON-RPC error; destructive MCP tools refuse unknown argument keys;
  `field:`-prefixed searches refuse by name; thread keys strip more reply
  markers and collapse whitespace.

## Errata and provenance (2026-10-19, issue #142)

**Policy.** A shipped release's notes are append-only. What v0.1.0 shipped
and measured is not rewritten; a later finding is added as a dated
*Correction* beside the claim it corrects, or as an entry here, naming the
issue and commit. Changes made after the tag are recorded in dated
"Unreleased" sections until the next release cut moves them into that
release's own notes; nothing here claims a release that did not happen.

**Provenance of the edits so far.** The original notes are `b8d1889`
(2026-10-07). After the tag they were extended, not re-released:

- `33ac7d1` (#114, 2026-10-18) appended "Unreleased — extraction fidelity".
- `40ef305` (#115, 2026-10-18) appended "Unreleased — webhook boundary".
- `2a325c9` (#119, 2026-10-18) added the dated #104 rate-proof correction
  and the #103 *Try it* correction. That edit also replaced the shipped
  *Try it* commands (`swarmail:v0.1.0`, `cargo install swarmail`) in
  place; the correction beneath them quotes the originals.
- `18374cc` (#165, 2026-10-19) appended "Unreleased — extraction and
  compat" and reworded the extraction-fidelity known limit's entity
  sentence in place (it had said the subset lasts "until the full WHATWG
  set is imported").
- This record (#142, 2026-10-19) adds the benchmark, coverage and *Try it*
  corrections above, the #118 entry and the corrections below.

**Commit messages that misstate what shipped.** History is not rewritten;
these are the corrections of record.

- `33ac7d1` (#114) says links are cut "with the full named-entity set".
  It shipped a 71-entry subset. The full table — all 2,125
  semicolon-ended WHATWG names — shipped in batch 4 (`18374cc`, #165;
  `src/extract/entities.rs`, proved there by
  `all_whatwg_entities_match_snapshot`).
- `582c73a` (#118) says `/api/v1/message/latest` "honours ?inbox= and
  ?query= via the shared search (limit 1)". It honours `?inbox=` only: a
  nonblank `?query=` is a 400 (search, then fetch the id), and `latest`
  reads `Store::latest`, not the shared search. Proof:
  `tests/compat.rs::latest_refuses_a_query_an_unknown_key_and_a_blank_inbox`.
- `582c73a` (#118) says thread keys strip "Re[n]: forms". They do not: a
  numbered `Re[2]:` is not a marker and stays in the fallback key
  (`src/threads.rs`, `subjects_normalize_by_stripping_reply_markers`).
- `40ef305` (#115) says an unheaderable webhook secret is refused "with
  the byte named". The refusal is fixed, value-free text — `webhook secret
  must be a valid HTTP header value: no control characters but tab` —
  so no byte of the secret is echoed (`src/webhook.rs`,
  `the_secret_domain_is_the_header_parsers`).

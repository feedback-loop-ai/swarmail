# Redacted tool evidence for eval trials

Part of #391, epic #164.

Decision: 0136 — [Paid token accounting and reference run](../../docs/decisions/0136-paid-token-reference.md).

A failed row tells a reader which fixture condition was missed. To distinguish a wrong tool choice from the right tool called with the wrong arguments, the reader needs the ordered, redacted arguments from that trial. Structural hashes already identify the calls. They cannot reconstruct the arguments. Capture therefore starts while the fixture owns the secrets, and the report publishes only a complete sequence corroborated by its journal join.

The authority for argument retention is accepted [0119 §4](../../docs/decisions/0119-eval-brokkr-recipe.md) and the dated amendment to [0075](../../docs/decisions/0075-eval-privacy.md). The decision proposed above concerns future measurement. Paid accounting still requires the operator's observations.

## Acceptance Criteria

1. Explicit matrix capture and report consumption are independently opt-in. With neither option, a fixed pre-change input produces byte-identical rows, JSON report and structural evidence, including filenames and absence cases. Historical rows work without capture. Evidence never supplies an outcome, an accounting fact or a missing row. Independent fixture-state replay and scored group results agree for the same inputs with capture enabled, disabled, missing or corrupt.
2. Capture only calls to the configured Swarmail MCP catalogue and the fixture's stdio MCP tool `eval_http`. Admit by actual destination and tool identity. Use the exact UTF-8 JSON argument bytes at the request boundary for the original length and SHA-256. A finished redacted capture must match the unique joined trial, full structural sequence, order, identities, lengths and argument digests. Bind each published entry to its structural ordinal and argument and result digests and lengths. Bind the companion to the complete structural file and index it by its own length and SHA-256. A present, verified zero-call sequence gets a nonempty JSON envelope.
3. Before retention redact the trial admin bearer and every registered sentinel wherever they occur, including decoded member names, nested strings and nested encodings. Registry completeness includes late registrations through trial teardown; the registry only grows during a trial, and a sentinel source unreadable at start or at seal makes it unusable. Deny by default: publish a value only when every name, string and number in it is provably plain after redaction, and withhold the whole trial's record with a typed reason otherwise. Reject ambiguous keys, every shape that is not plain and every residual match. The mode may withhold evidence, and over-refusal is the accepted cost. The guarantee is exact: the bearer and every registered sentinel are refused, never published, in their raw, ASCII-case-folded, JSON-escaped, `%XX` (with `+` as a space), nested-JSON, numeric-value, base64, base64url and base32 (including when split into chunks by separators), hex (joined by any separators) and quoted-printable spellings. No check sees ROT13 or another letter substitution, a reversal, ascii85 or another alphabet not listed, a decimal or other code list (`115,101,...`, `0x73,0x65,...`), or a literal split across fields or calls; that is the boundary of accepted 0075 §9, as the operator accepted it. Original arguments, registry, tool results, prompts, raw CLI output, model text and reasoning are never evidence. Transcripts therefore cannot explain an agent's private rationale.
   Ruled by the operator on 2026-11-21 (review return 4). This replaces the closed set of supported encodings from review return 3, which published a sentinel spelled in base64, HTML entities or another case. "Plain" means printable ASCII with no backslash, no `%XX` escape, no `&...;` entity, no two quoted-printable escapes in a row, no run of 37 or more of `A-Z a-z 0-9 + - _ =` (a path or URL separator `/ ? & # .` breaks a run, so the fixture's own routes publish), and no 64 hex digits in one run once every character that is not a letter or digit is deleted (a non-hex letter breaks it). Quoted-printable is also a decoded layer of the residual search, and so are base64, base64url and base32 with chunk separators (whitespace, `.` `,` `:` `;` `|`) removed, at every alignment (review return 9). Literals are matched ignoring ASCII case, and every literal that reads as a decimal number (after trimming whitespace, a leading `+` and leading zeros) by value and by digit string. Sentinels must be at least 32 bytes of printable ASCII other than `?` (review return 5), so every base64, base64url, base32 and hex spelling of one holds an unbroken run of at least 40. Journal-derived free text is published only as its SHA-256 (non-owned tool names) or when plain (the run id). Operator ruling 2026-11-21 (review 5): `=` counts in a run again and quoted-printable and separator-joined hex are refused, closing the regression return 5 opened. The "never in any spelling" wording is replaced by the exact list above. A lone `=XX` is not refused, because it is the shape of every `key=value` whose value starts with two hex digits.
4. Bound each original and encoded redacted argument at 8192 bytes, at most 256 calls and 65536 bytes of original arguments per trial, and the serialized companion at 65536 bytes, inclusive. Withhold the whole companion for one refused call, including the last. A typed absence carries exactly one of the existing upstream unavailability reasons or, for a present fact, one of `capture_missing`, `registry_unavailable`, `unknown_tool`, `value_too_large`, `trial_too_large`, `invalid_argument_encoding`, `residual_secret`, `binding_mismatch`, `evidence_write_failed`. Publish no prefix or placeholder. Untrusted text never enters diagnostics. Failure to safely emit a report or its index fails the command with a finite diagnostic.
5. Count the eight existing failure classes over validated failing rows (including harness errors), before filtering for evidence. Visit observed classes by decreasing count, breaking ties by bytewise class name. Within each visit consider ascending bytewise trial ID until three complete eligible trials are selected or the class is exhausted. Under `transcripts/` write an ordered index with class total, eligible and selected counts and up to 24 JSON leaves, each containing the validated row, failure class and verified redacted sequence in ordinal order. Cap each leaf at 128 KiB and the index at 64 KiB. Skip a leaf exceeding the cap with a typed size disposition. Zero eligible rows still yields class counts. Permutations of equivalent input yield identical selection and transcript bytes.
6. A rendered report page has a tokens-per-success cell for every paid group, including reporting without a journal. Print the numeric figure or literal null and the typed explanation. Preserve §3's scored population, missing-fact precedence, checked sum and separate cached count. An unavailable figure never displays as zero or a dash.
7. Through the offline stand-in and normal CLI, prove the oracle passes, the null control fails and both preserve the built-in journal disposition. Use an offline external slot for a present join through both configured tool paths. Search every output file as bytes, plus stdout/stderr, for independent bearer and sentinel canaries on success and refusal. Plant an unredactable value. Prove each typed absence, the bounds, default-byte equality and score independence.
8. The two eval READMEs and 0119 task ledger distinguish delivered tool diagnostics from the unmeasured paid runs. The operator runbook names executable steps, F1/F2/F5 observations and dated addenda per family. Preserve pre-launch/pre-private-read `driver_contract_unknown`. Index 0136 as proposed. No direct-launch accounting, paid smoke, collection, freeze, publication or push in this delivery.

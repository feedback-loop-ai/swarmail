## Findings, panel rulings and project structure

1. **Driver pin.** Adopt simplicity's removal of the process-global set/remove pair in both the nested integration test and the inline test in `evals/src/wrappers.rs`. The latter edit is necessary because the unsafe pair lives there under test configuration. Record the exception in the ledger. In `evals/tests/wrappers_launch/nested.rs`, mutate only the copy installed by `common::paid::install_native`. Adopt robustness's restoration check at the point of use. Compare the reselected digest, restored private bytes and profile-adjacent stand-in using the existing hash helper, with path/read failures distinguishable. Keep the actual verifier call. This costs a local file read but identifies the failing input while it still exists. Debug admission hashes the adjacent build product (one directory up from deps), and never consults the variable. Removing the unsafe mutation alone cannot establish the cause of the Ubuntu refusal. Trace any divergent path or writer before claiming it.
2. **Grant lifetime.** Both positions identify a sufficient failure mechanism in `evals/tests/wrappers_launch/mod.rs`. The two success constructions use the current integer second as the last acceptable second. After probing, spawning and receiving a packet, grant::answer compares that horizon with a fresh clock reading. Reuse common/paid.rs's now and HOUR and the existing bound helper for both constructions. Capture an epoch, choose a valid horizon comfortably beyond the bounded child exchange and give the synthetic credential a later expiry. Build argv and coordinator expectation from the same binding. Place the insufficient-margin horizon beyond credential expiry and retain deliberately expired fixtures. Use the existing pure answer proof with explicit successive seconds to exercise rollover and expiry without a sleep. This may require a test-only assertion in grant.rs if existing coverage is insufficient. Document such an edit in the ledger. Keep the live credentialed socket proof. Neither a grant retry nor an ancestry fallback can distinguish an expired binding from an invalid sender.
3. **Report admission.** The bound probe in `evals/tests/report.rs` uses stand-in mode ok. Both agents_file calls write the same agents.json, so the later argv-only fixture replaces the profile declaration and puts the oracle first. Dispatch reaches trial.sh and acquires the fixed /tmp/swarmail-evals-<uid>/trial.lock outside the cooperating trial_scope. A competing oracle slot in agreeing_case can then receive concurrent_trials_refused. Matrix stops and fills an unstarted suffix, leaving one logged request even though it emits three rows. The fixed root ignores HOME and TMPDIR, including macOS's /var alias. Give the declarations distinct private paths and each probe its own request log. Use common::tempdir and resolve_root before safe_root wherever paths are validated. Choose simplicity's no-row stand-in for these preflight probes. It logs dispatch and exits before trial.sh on either OS, even if a negative control regresses. Check the precise outcomes in AC3. Adopt robustness's file-identity and downstream-dispatch checks. Its alternative trial_scope around the positive probe would serialize another worker and preserve irrelevant seat work. The chosen probe gives up execution beyond dispatch here. The guarded agreement and overlap tests continue to exercise actual admission. Audit neighboring dispatch-capable fixtures for that ownership rule.

## Risks

- If the restored inputs agree yet admission refuses, record paths, hash results, build profile and refusal. For a still-refused positive grant, distinguish synthetic horizon and answer time, binding equality and sender identity using test evidence. Keep credentials and raw CLI output out of the ledger. Stop on evidence of a production defect.

- Preserve direct Linux cfg attributes on Linux helpers and existing platform guards for /proc-dependent launches. The portable report proofs must execute on macOS. Measure affected test time against comparable pre-change runs and record conditions and noise. Keep incremental CI time to a few seconds.

# Count paid tokens through the nested driver

Decision: 0138

Part of #404, #391 and #164. The paid baseline can already authorize a product, run its controls and commit individual trial scores. Its token comparison needs the cost of failed trials as well as passes. The November 23 smoke found that the outer exec adapter consumes the nested driver's stdout. A successful driver process can even exit without launching a CLI. Reading the journal or using process exit alone would mismeasure the models.

The wrapper will act as the engine for the nested driver. Only the harness may attach its typed session usage to the scored trial. The runner retains ownership of cancellation, cleanup and grading. The proposed record defines how a reader recognizes committed accounting evidence. [Proposed decision 0138](../../docs/decisions/0138-nested-driver-usage.md)

The operator ruled the accounting channel in the November 23 addenda to [0119](../../docs/decisions/0119-eval-brokkr-recipe.md) and [0136](../../docs/decisions/0136-paid-token-reference.md) at Git object `64f4763e`. The accepted [0137](../../docs/decisions/0137-paid-baseline.md) profile amendment is at `33be71de` (PR #407). These objects supply the dated text missing from the design base.

## Acceptance Criteria

1. From the paid baseline entry point, an explicitly authorized nested product selects the matching driver in matrix, trial and wrapper. Direct paid selection still works. Fresh oracle and null controls exercise the paid coordinator and receive their established grades. Resume rejects changes to route or verified executable identity. Unimplemented selectors still refuse with `driver_contract_unknown`.
2. An offline peer observes hello/capabilities, start/accepted, zero or more checkpoints, one result, shutdown and orderly termination. Start identifies effect, attempt and seat. Its input contains exactly feature, phase, seat, role_path, workdir, result_path, allowed_results and context. The charter exists, the goal reaches start, and the agent can write a fresh result. Only the observed family flags follow the separator. Invalid order, identity, encoding, framing, bounds or completion yields a typed harness failure. Exit zero with no launch yields harness_error, never gave_up.
3. Before spend, verify the absolute executable path and published SHA256SUMS digest for the Linux x86_64 brokkr v0.15.2 release separately from the delivery engine. Direct and nested selection admit exactly native Claude Code 2.1.329, native codex-cli 0.166.0 behind Volta and interpreted dsh 0.2.2-rc.1. Each requires its recorded exact banner and verified bytes. Refuse other versions, superseded selectors, shims and altered digests before a spending spawn. For dsh bind the absolute native Node path, exact version and SHA-256, package root, entry and relative-path SHA-256 of every package file. Diagnose changed runtime, changed file, extra file, missing file, escaping link and shim separately. Observe the verified runtime executing the verified entry directly on both routes.
4. In the trial box, all families can read the four declared DNS inputs, reach only selected auth/config projections and resolve the verified executables through the controlled PATH. HOME and required writable state belong to the trial. dsh sees its profiles overlay and only its selected route key by name. An actual result write under the selected Codex sandbox class succeeds while protected sources reject writes. Tests use inert inputs and retain no credentials or raw streams.
5. Each committed nested trial has one harness-authored usage companion, source via_brokkr_driver, bound to its trial_id and attempt. Each of input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, num_turns and total_cost_usd independently holds a valid value or a finite unavailable reason. Preserve explicit zero. Distinguish absent, malformed and conflicting final data. An identifiable repeated final counts once. Per-turn or cumulative observations alone cannot establish a session total. Missing usage alone cannot change a valid grade.
6. For each report group, report --page divides the checked sum of input plus output of every scored trial by its number of passes. Cache reads and writes are separate. Incomplete attribution, missing required counts, overflow and zero passes each yield typed unavailability. A legacy row without nested evidence remains readable under its applicable schema. Journal tokens cannot fill a nested gap.
7. journal-facts.sh uses export --run and real R.ndjson. Match effect/requested.payload.seat to effect/checkpointed.payload.checkpoint by run, effect and attempt and verify trial identity. Preserve existing journal authority for other facts. Tests cover interleaving, retries, ambiguous ownership, missing accounting, invalid input and failed export.
8. Update evals/README.md, evals/wrappers.md and specs/eval-brokkr-recipe/tasks.md. Offline delivery runs free proofs only. Feature completion additionally requires one explicitly operator-approved authenticated session per family through the finished route, with attributable non-null input and output. These three sessions are the only paid acceptance step. The prospective reference remains the separately declared 16 default tasks × six models × five trials of 0136.

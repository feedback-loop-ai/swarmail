# Count paid tokens through the nested driver

Decision: 0138

Part of #404, #391 and #164. The paid baseline can already authorize a product, run its controls and commit individual trial scores. Its token comparison needs the cost of failed trials as well as passes. The November 23 smoke found that the outer exec adapter consumes the nested driver's stdout. A successful driver process can even exit without launching a CLI. Reading the journal or using process exit alone would mismeasure the models.

The wrapper will act as the engine for the nested driver. Only the harness may attach its typed session usage to the scored trial. The runner retains ownership of cancellation, cleanup and grading. The proposed record defines how a reader recognizes committed accounting evidence. [Proposed decision 0138](../../docs/decisions/0138-nested-driver-usage.md)

The operator ruled the accounting channel in the November 23 addenda to [0119](../../docs/decisions/0119-eval-brokkr-recipe.md) and [0136](../../docs/decisions/0136-paid-token-reference.md) at Git object `64f4763e`. The accepted [0137](../../docs/decisions/0137-paid-baseline.md) profile amendment is at `33be71de` (PR #407). This continuation includes those addenda, the three amended profile verifiers and the caller at 4d1545cf. The November 24 ruling retains all 16 tasks, including the three-session inbox-isolation trial, and requires a verified launch route before spend. The staged release and sanitized smoke provide offline protocol evidence.

## Acceptance Criteria

1. From the paid baseline entry point, an explicitly authorized nested product selects the matching driver in matrix, trial and wrapper. On the host, admission requires the authorized baseline slot’s current paid-launch binding under accepted 0137. Under the recipe, admission requires verification of the effective F5 binds inside the trial seat. Matrix, trial and wrapper refuse an unbound nested paid selection before credential access or spending spawn. A selection or launch-report pipe alone grants no admission. Direct paid selection still works. Fresh oracle and null controls exercise the paid coordinator and receive their established grades. Resume rejects changes to route, verified executable identity or selected Codex posture. Unimplemented selectors still refuse with `driver_contract_unknown`.
2. An offline peer observes hello/capabilities, start/accepted, zero or more checkpoints, one result, shutdown and orderly termination. Start identifies effect, attempt and seat. Its input contains exactly feature, phase, seat, role_path, workdir, result_path, allowed_results and context. The charter exists, the goal reaches start, and the agent can write a fresh result. Only the observed family flags follow the separator. A failed result before acceptance is a start refusal. An accepted attempt ending at EOF without a result is an indeterminate harness error. Invalid order, identity, encoding, framing, bounds or completion yields a typed harness failure. Exit zero with no launch yields harness_error, never gave_up. After a protocol error past acceptance or terminal result, close stdin, bound drain and exit by a short grace within the trial budget, and kill and reap a lingering driver. Preserve the typed receipt and cancellation precedence.
3. Before spend, verify the absolute executable path and binary digest of the extracted Linux x86_64 brokkr v0.15.2 executable, tracing it to the archive digest in SHA256SUMS, separately from the delivery engine. Production NestedSelection requires both release constants in plan.md. A self-consistent replacement with the expected banner refuses before execution. Direct and nested selection admit exactly native Claude Code 2.1.329, native codex-cli 0.166.0 behind Volta and interpreted dsh 0.2.2-rc.1. Each requires its recorded exact banner and verified bytes. Refuse other versions, superseded selectors, shims and altered digests before a spending spawn. For dsh bind the absolute native Node path, exact version and SHA-256, package root, entry and relative-path SHA-256 of every package file. Diagnose changed runtime, changed file, extra file, missing file, escaping link and shim separately. Observe the verified runtime executing the verified entry directly on both routes.
4. On the recipe route protect the four DNS inputs, selected install trees and source config/auth with verified read-only binds. From the mounted trial namespace a write to an otherwise writable inert source must fail while a write to the private result succeeds. On the host baseline use the direct-wrapper confinement accepted in 0137. On both routes, all families can read the four declared DNS inputs, reach only selected auth/config projections and resolve the verified executables through the controlled PATH. HOME and required writable state belong to the trial. dsh sees its profiles overlay and only its selected route key by name. The real v0.15.2 driver must launch inert CLIs for all three families inside the trial boundary. For Codex the selection records a typed inner sandbox class. Admit only read-only and workspace-write. Refuse danger-full-access with a typed pre-spend reason. The effective class must agree across argv, ToolSurface::declared, retained provenance and resume. Its stand-in must write the result while protected mounts reject writes. Criterion 8 separately requires the real Codex write under the same class. Tests use inert inputs and retain no credentials or raw streams.
5. Each committed nested trial has one harness-authored usage companion, source via_brokkr_driver, bound by digest in the final metadata commit to trial_id, slot, assignment attempt and verified profile. Record an ordered roster of all expected agent identities and driver attempts, independently of arrival order. A three-agent trial --task inbox-isolation with successful exchanges receives its application grade. Sum each field across all sessions with checked arithmetic. If any session lacks the field or the sum overflows, that field is unavailable. A lost receipt leaves a roster entry and preserves sibling observations. Each of input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, num_turns and total_cost_usd independently holds a valid value or a finite unavailable reason. Preserve explicit zero. Distinguish absent, malformed and conflicting final data. Use the selected family’s exact final step in plan.md. An identical final repeated by the driver counts once. Agent-authored result inputs have no accounting authority. Per-turn or cumulative observations alone cannot establish a session total. Missing usage alone cannot change a valid grade.
6. For each report group, report --page divides the checked sum of input plus output of every scored trial by its number of passes. Cache reads and writes are separate. For valid committed evidence, an unavailable required session count, group overflow or zero passes yields typed metric unavailability. A scored nested row without a valid companion refuses scoring, including on offline report and resume. Verify both digests and ownership against the assignment, expected roster and committed row. Reject orphan, swapped and duplicate-owner companions. Schema-2 rows contain no nested_usage field and pass the historical strict decoder. Historical free/direct rows remain readable. Journal tokens cannot fill a nested gap.
7. journal-facts.sh uses export --run and real R.ndjson. Match effect/requested.payload.seat to effect/checkpointed.payload.checkpoint by run, effect and attempt and verify trial identity. Preserve existing journal authority for other facts. Tests cover interleaving, retries, ambiguous ownership, missing accounting, invalid input and failed export.
8. Document hard-deadline receipt loss, its effect on group metrics, and the nested terminal-result requirement. Update evals/README.md, evals/wrappers.md and specs/eval-brokkr-recipe/tasks.md. Offline delivery runs free proofs only. Feature completion additionally requires one explicitly operator-approved authenticated session per family through the finished route, with attributable non-null input and output. These three sessions are the only paid acceptance step. The prospective reference remains the separately declared 16 default tasks × six models × five trials of 0136.

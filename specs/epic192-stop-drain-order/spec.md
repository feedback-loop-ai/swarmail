## Feature and rationale

Protect the existing shutdown and startup ordering with deterministic tests that fail when the relevant operations move. Observe the actual HTTP drain-deadline selection, and correct comments that infer storage progress from a request gauge. Existing successful shutdown tests do not prove these properties: a stop may return after the wrong arm ran, and a webhook delivered before stop says nothing about when `drained` was sent.

## Panel synthesis and explicit rulings

1. **Adopt simplicity's private tracker test; reject robustness's additional completion hook in a real protocol task.** An inline child test may insert a test-owned held task into the actual private serve `JoinSet` of a real `run_on` server. It must poll the actual stop future and inspect its actual drained watch. This directly tests the tracker ownership obligation without another production seam. Price of rejecting the extra hook: the proof does not locate a protocol task or storage commit at a specific stage. Existing real-wire storage/fan-out tests supply complementary evidence; no such stage is claimed by the held task.
2. **Adopt robustness's actual-arm receipt and graceful negative control; adopt simplicity's single relocated stalled-body scenario.** Move the decisive real-wire scenario beside `api::serve` so a private `cfg(test)` witness is visible. Remove the old duplicate ten-second scenario after the stronger one passes, leaving a cross-reference. Price: the decisive scenario runs in the library test target rather than the public integration target. Keeping two identical waits adds runtime without proving another requirement. Public API hooks, shipping metrics and feature flags are rejected.
3. **Adopt both panels' shared startup orchestration, with robustness's explicit mutation tests for each stream and late registration.** An isolated poll-helper test cannot protect the relationship with startup. The production caller must invoke the tested ordering owner before startup work can begin. Price: small private factoring and its coverage obligation; an all-purpose lifecycle/signal abstraction is rejected as unnecessary complexity.
4. **Adopt both panels' stage-precise prose and preserved residuals.** No outbox, storage queue, stronger socket-close guarantee, changed timer, or tracking of all detached work. The losing stronger design would change accepted semantics and expand storage/dispatcher ownership for a test-repair story. The accepted cost is explicitly incomplete accounting for detached late work, as already ruled.
5. **Reconcile file placement by 0020's cold-path rule, not minimal file count.** Prefer branch-stable inline tests. If a concrete failure-only read diagnostic or watchdog requires a cold path, isolate that test in an authorized `cfg(test)` harness and identify the exact cold path in implementation evidence. Neither seam access alone nor a preference for zero new files overrides [0020](../../docs/decisions/0020-concurrency-tests-and-the-coverage-gate.md).

## Acceptance Criteria

- **AC1 — stop order (8.1).** A fresh real server has a per-test held task entered in its actual serve tracker. Subscribe to drained before stop. Explicitly drive the pinned real stop future to Pending while release is withheld and assert drained is false. Release the serve hold, then observe drained true while a separately held task in the actual dispatcher tracker keeps stop pending; release that task and require stop completion. No sleeping or unpolled-spawn observation establishes order. Moving only the actual drained send ahead of the serve-join loop must fail the unchanged test; restore and rerun green.
- **AC2 — deadline selection (8.4).** A real TCP client sends an incomplete seed body with `Expect: 100-continue`, reads the complete interim response, and retains its socket and incomplete body through shutdown/serve completion. Assert exactly one per-invocation receipt from the actual selected deadline arm. A separate ordinary graceful completion emits none. Removing the receipt must fail the stalled-body assertion; bypassing the deadline while the body stays open must fail the bounded liveness guard. Restore green after each mutation. Time elapsed and coverage of the arm are not the selection oracle. Keep the production ten-second timer unchanged.
- **AC3 — truthful comments (8.2, 8.5, 8.6).** Review lifecycle/binary docstrings and adjacent comments, the allowed SMTP drain comment, and directly related lib lifecycle comments against actual code and accepted rulings. No unconditional parked-insert commit, unconditional duplicate, gauge-as-queued-commit, stale 300 ms sequencing, or all-process-tasks-owned claim remains in these sections. Gauges witness only their own stages; interrupted outcomes remain refused-or-committed, never partial, with possible no-reply uncertainty.
- **AC4 — signal ordering (8.3).** A deterministic test exercises the same private orchestration main uses for Unix serve startup. Per-test signal probes record each first poll; the startup continuation asserts both already happened when invoked, including immediate startup with no yield. Background watcher progress cannot satisfy the assertion. Independently omitting the SIGINT eager poll, omitting SIGTERM's, and deferring registration until after startup must each make the test fail, followed by restoration to green. No unit test sends process-global signals or uses a shared global handler registry as its oracle. Existing child SIGINT, SIGTERM and forced second-signal proofs remain.
- **AC5 — isolation and invariants.** Every seam is private, test-only, per-invocation or consumed in an isolated current-thread test runtime before awaiting. Both installed and uninstalled paths are exercised. No mocked protocol loop, sleeps as synchronization, probabilistic scheduling requirement, new dependency/license allowance, production test configuration, excluded production line, or modified runtime shutdown fence. Inline/harness placement follows 0020 with concrete cold-path evidence. No out-of-lane edits.
- **AC6 — executed delivery evidence.** Implementation records test names, commands, exits, evidence paths, each narrow mutation patch/digest and assertion failure, restoration checks and green reruns. Run the entire [house-rule gate inventory](../../docs/house-rules.md#gates--part-of-every-change) and configured pinned verification proofs, including design-check selftest, delivery tamper-boundary, recipe structure and expected no-match native-tls proof. Maintain exact 100% lines/branches/functions and report blockers honestly. The deterministic final design check alone advances this design; subsequent implementation, verification, all four fixed independent reviewers and any security hold remain required.

## Residuals and exclusions

A late detached blocking commit may outlive tracked sessions and miss the dispatcher's ledger. An HTTP deadline ends serve waiting, not every detached socket; process exit/runtime teardown owns that residual. A retained Store may retain writer locks after stop. Embedded producers must quiesce. Interrupted work may commit without reply or refuse; memory-only storage promises no restart durability. Webhooks remain bounded best-effort observed work, not a durable outbox. Existing cap/pruning, DATA/trickle, chaos and TLS failure policies remain intact; this lane adds no availability, crash-recovery or certificate-expiry guarantee.

## Panel rulings

- Adopt simplicity's direct baseline CLI, existing trial owner and retained evidence. Reject looping the public matrix command per chunk. A restarted suffix would generate fresh coordinates and could rerun a committed trial. The cost of reuse below the matrix entry point is making its assigned-cell execution callable independently.
- Adopt robustness's operator-pinned digest and exact version probe over measuring whichever binary occupies a path at first use. The operator must maintain three installation pins. Only the private v2 selection holds the CLI path; the run manifest records the checked binding as public identity (profile, version, sha256) and no path. Only canonical identity leaves the private boundary.
- Choose robustness's finite route-specific attestation for dsh. Simplicity's static-key exemption lacks evidence for both routes. Preparing a key plus horizon on rotation costs operator time but makes both the margin check and its refusal testable.
- Adopt simplicity's single score authority and robustness's exclusive writer, prelaunch attempt binding and conservative cleanup rule. Per-attempt writes cost I/O. Ambiguous forced death can require operator intervention. Advancing a chunk cursor or treating a released lock as proof of cleanup could silently duplicate a paid launch.

## Risks

- Login expiry is a local scheduling bound. Quota and revocation can still cause measured failures. Keep the six-model product intact and record actual outcomes.
- Trusted installation immutability covers the narrow final check-to-exec interval. Reject unverifiable launchers and changed pins. Diagnostics expose only finite causes. Test canaries in rejected version banners as well as credentials.
- Partial artifacts and surviving descendants make blind retry unsafe. Test both sides of the commit fence, duplicate/tampered evidence, simultaneous resume and final-output interruption. Per-file atomicity covers process interruption. Power-loss durability is outside this contract.
- CI time is scarce. Reuse the existing real control proof, use the smallest approved tier for the command test, and use bounded event barriers and lightweight worker stand-ins for repeated crash permutations. Measure incremental wall time in the ledger. Keep portable parser/policy tests runnable on macOS and apply direct item-level Linux cfgs where required.

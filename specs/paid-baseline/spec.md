# Run the paid baseline from one operator command

Part of #393, epic #164. The November baseline needed a private driver to gate paid work on controls, select a login with enough time left and continue a stopped run. Its rows identified the wrapper configuration but could not tell a reader which CLI binary ran. Move that procedure into `swarmail-evals baseline` so the operator can authorize one product and later audit or resume that same measurement. The historical five-model quota exception applies only to that run. [Published deviations](../../docs/evals/baseline-2026-11-01.md#deviations-from-the-run-plan)

Decision: 0137

[Paid baseline contract (accepted with an amendment, 2026-11-23)](../../docs/decisions/0137-paid-baseline.md)

## Acceptance Criteria

1. For the default product and each supported tier, print the machine-readable plan before checking spending authority. Enumerate the control slots and nominal task-major chunks with their five repetition indices, all six ordered declarations from `evals/agents-baseline.json`, catalogue and product IDs, deadlines, concurrency 1, per-family freshness rules and selected margin. Show a sequential wall-time estimate in minutes with its calculation and the additional, unpredictable time for preparation, cleanup and renewal. The default has 32 controls and 480 paid slots. Deliverability has two and thirty. `--dry-run` succeeds with absent private files, launches zero processes, creates no output and reads no credential.
2. Start and explicit `--resume` require `--authorized-product ID` matching the printed ID exactly. Missing and mismatched authorization produce distinct named refusals, exit 2 and zero launches. A declaration, coordinate or deadline change invalidates approval. Output location and current credential eligibility do not influence the ID.
3. Before spending, validate and record all planned families. Each contract binds the direct wrapper profile, absolute CLI path, exact supported version, locally pinned and measured SHA-256, and validated auth-file shape. Name the family and finite cause for each refusal, including absent contracts, wrong version, unsupported auth shape and digest mismatch. Check the original binding again on resume and at launch. Only the private selection holds source paths. Trial rows expose the verified canonical version and digest beside the existing wrapper disclosure, including setup, failure and refusal rows belonging to an admitted product. These identify the approved binary for a never-started row. Preserve the row's execution outcome. Preserve the wrapper executable's separate provenance and historical reader rules.
4. In a fresh run, run one oracle and one null control for each task, validate every retained result, fixture binding and expected outcome, then admit paid work. On resume, reuse only validated controls of this run. A missing gate, failed oracle, wrong null failure class or corrupt evidence authorizes zero paid slots. Hold concurrency at one through owned cleanup under accepted 0076.
5. Dispatch the earliest outstanding eligible task × model chunk, preserving nominal task, model and repetition coordinates across deferrals. At entry to each chunk, including partial chunks on resume, require remaining validity **at least** `--freshness-minutes` (default 70, checked positive integer). Claude uses source `expiresAt` in milliseconds. Codex validates source `last_refresh` and reads bounded expiry evidence from its access token. Copy time gives no validity evidence. For each dsh route require a private operator-attested valid-through time bound to the selected key as specified in 0137. Unknown or malformed validity evidence refuses by family/route before spend. A valid but too-close credential defers that route. Other eligible chunks run first. With none eligible, print the blocked families and renewal reason and wait interruptibly for external renewal. Recheck any credential replacement before use. No slot is consumed by deferral.
6. A fresh private output directory contains an immutable manifest, retained attempts, controls.jsonl, paid.jsonl and report.json upon completion. One writer owns the run. Bind every score to its original planned slot and trial evidence. Interrupting between chunks or mid-chunk preserves every committed score, including measured failures. Resume runs only outstanding coordinates and reproduces the exact planned slot set in canonical order. Refuse duplicate or inconsistent evidence, identity drift, competing writers and unsafe roots before further launch. Preserve evidence of unscored attempts. Unproved cessation stops the run for operator cleanup confirmation. An interrupted request may have incurred a provider charge before its local score committed.
7. Keep existing scoring, report and exit precedence. Finishing or reopening a fully committed product launches no additional trials. Recover missing derived output through private atomic no-clobber publication. Conflicting existing bytes refuse. Tokens per success stays unmeasured under proposed 0136. Credentials, claims, raw banners and private CLI paths stay out of diagnostics, rows and reports. No token enters argv.
8. Offline proof exercises the normal baseline command for a full tier with fake direct CLIs, including actual control gating, interruption, freshness and identity checks. Document invocation, private inputs, limits and recovery in both eval guides and the run plan. Date the status and distinguish stand-in proof from operator-owned authenticated interoperability.

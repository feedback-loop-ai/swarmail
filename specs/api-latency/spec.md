# API latency: native and MCP

Created: 2026-11-17. Status: draft implementation specification.
Backlog: issue #360, story B of #349/#351. Base: story A, 9ac77db.

## Authority and purpose

Implement accepted [0132](../../docs/decisions/0132-mail-comparison-protocol-v4.md), especially §§4, 6, 7.4, 9–11 and Implementation B, including its acceptance note. Measure the cost of an exact requested result; publish failed, unsupported and inexact answers alongside successful latency. Native and MCP are separate surfaces, with bridge overhead included in MCP time.

This implements an existing ruling without amending it or changing a server public contract; no new decision is proposed. Preserve [0001](../../docs/decisions/0001-synchronous-insert-lossless.md), [0002](../../docs/decisions/0002-awaits-subscribe-before-checking.md), [0003](../../docs/decisions/0003-oldest-only-pruning.md), [0005](../../docs/decisions/0005-extraction-at-ingest.md) and [0129](../../docs/decisions/0129-agent-suite-comparison.md). No server src/ changes, new packages in either lock, deny.toml changes, adapter tools or frozen historical byte changes. Stream waits, test execution, freeze, collection and headline publication remain C–E.

## Panel synthesis

Adopt simplicity's seven concrete API-family modules shared by #[path], narrow transport reuse and single launch owner. Reject plugin machinery, duplicate clients, a second supervisor, speculative retries and sweeping legacy observer refactoring: they add maintenance without required capability.

Adopt robustness's authored fixture ledger, strict pagination, destructive scheduling, finite deadline accounting and globally distinct MCP IDs. Reject timing successful status codes or repeatedly deleting/clearing empty state. The losing simplicity choice costs fixture setup, typed records and concurrency proofs; these are necessary to measure equal results.

Reconcile resource ownership through existing hold, adding only an opt-in window-control boundary. Reject arbitrary endpoints lacking enforced launch evidence. Reject robustness campaigns outside this measurement boundary: no server, durability, TLS, webhook or chaos campaign. Preserve all existing house proofs.

## Acceptance Criteria

1. **Clients and evidence.** Add seven API-family modules under benches/mail_compare/clients/: Swarmail, Mailpit, MailHog, MailSlurper, smtp4dev, Inbucket and GreenMail, with typed results. Preserve distinct product identities for official, source-build and Alkemio MailSlurper; share behavior only where captured evidence agrees. Evals compiles the same modules by #[path], using packages already available in both locks. Every invoked route, paging rule, filter and scope cites a lock-v5 document rechecked for path, size and digest. GreenMail v4 reads REST, not legacy POP3. Missing evidence refuses preflight, never invents unsupported capability.
2. **Matrix.** Native measures list, search, get, extract_code, extract_link, delete and clear. MCP measures supported operations plus future wait using revision 2025-03-26: Swarmail's native POST /mcp and the existing Mailpit, MailHog and MailSlurper-source-build adapters through the bridge. smtp4dev, Inbucket, GreenMail and Alkemio publish `no MCP surface`; official MailSlurper publishes blocked `does_not_start` without launch. Adapter delete/clear are cited `not_supported`. Distinguish unavailable native filters from supported client-filtered complete scans and narrowest global clear; label scope, inbox isolation, ingest extraction and polling. Runtime errors cannot change capabilities.
3. **Exactness.** Author expected bytes, subject, from, to, text, HTML, code and labelled URL independently of responses. Setup resolves server IDs without learning expected contents from the server. List equals precisely the measured recipient's ten IDs after full paging and exact filtering; search recipient AND subject equals one ID. Reject duplicates, missing/extra IDs, repeated/incomplete pages and absent required fields. Get follows v3 fidelity: only previously documented discrepancies are `inexact_fidelity`, retaining latency but unranked; new wrong/partial results are `wrong_result`. Code and link must equal the authored six-digit code and fixed labelled URL. Swarmail reads ingest fields; competitors read through the measured surface and run the unchanged oracle extractors inside elapsed time. No native HTTP fallback in MCP measurements.
4. **Fill.** Each surface/target/repetition/fill chunk owns a fresh instance. Fills 0/1,000/10,000/100,000 use seeded v3 corpus, eight reused SMTP sessions and 100 round-robin background recipients outside measured scopes. Setup and verification are untimed. Within 300 seconds establish accepted and confirmed retained counts; otherwise publish `fill_not_reached`, count reached, and blocked cells. Never reduce fill or retry ambiguous sends. Before measured fixtures record idle_fill_N: five idle seconds, last two sampled, plus allocated disk bytes. Label measured-inbox versus shared-store differences and preserve the 150,000 cap.
5. **Cells.** Ordinary cells use 1/8/32 closed-loop workers with independent keep-alive connections. Initialize before warmup. Twenty warmups are a cell total, followed by a shared queue of 100 measured operations or an absolute five-second deadline, whichever first. Include paging/filtering/decoding/extraction/bridge time; no cache, prefetch, index or expected-ID hints. Every nested call uses remaining budget. Stop assigning at cutoff, retain one terminal row per started operation (including timeout/cancellation), and count only untouched slots as unstarted. Warmup is separately bounded to five seconds; failed warmup blocks measurement. If calls remain unresolved at cutoff, retain failures, block subsequent cells and tear down the launch: cancellation does not prove absence of server-side mutation.
6. **Destructive operations.** Read cells precede destructive cells and use a stable ten-message set. Each delete concurrency cell preallocates 120 distinct victims (20 warmup, 100 measured) and ten survivors in its own scope. Each recipient-clear concurrency cell preallocates 120 disjoint ten-message scopes (20 warmup, 100 measured), plus an external ten-message sentinel scope. Preparation is before warmup, never inside a measured window. Keep survivors, unstarted fixtures and background fill until final global clear. Untimed postchecks compare the complete expected retained ledger as a batch, proving victims removed and other mail, especially outside recipient scopes, preserved. Mismatches invalidate affected successes as wrong_result; uncertainty never becomes exact success. Global clear is one invocation per surface/fill/repetition, last, with no destructive warmup, no concurrency replication and no quantiles; verify complete emptiness afterward. Compute total fixture growth, including waits, before launch and require fill plus fixtures below 150,000; never work around pruning.
7. **MCP and wait.** Benchmark clients have globally disjoint request IDs, including initialization, across one shared bridge/adapter. Preserve bridge/adapter admission limits and classify busy refusals by source; no serialization workaround or retries. Future wait uses fresh recipient/subject per attempt, starting the wait request before coordinating SMTP dispatch without sleep or a claim of server registration. Check exactly that message. Record send, acknowledgment, wait call/return on one monotonic clock with signed ack-to-return offsets. Adapter waits stay labelled polls. Ordinary cell budgets apply; one coordinated sender/waiter is one logical worker, at most 32 attempts concurrently. No fixture exists before its own attempt.
8. **Resources and lifecycle.** Reuse story A's enforced 2 CPU/2 GiB/no-swap/4096-task leaf, CPU placement and 100 ms sampler. Each window retains start/end cpu.stat, memory.events, attributed samples and raw deltas; setup, warmup and postchecks are outside it. MCP requires the hold launch and actual final cleanup receipt including cgroup_removed, plus bridge/adapter cleanup. OOM/target exit are measured failures, never retried. Infrastructure/interruption/uncertain cleanup leaves the run incomplete. Target failure exits 1, infrastructure failure exits 2; no resume, overwrite or fabricated seal.
9. **Reports and admission.** Each terminal row identifies run/launch/chunk, product, surface, repetition, fill, operation, concurrency, worker/index, timestamps, outcome, exactness, citation and scope. Planned = started + unstarted; started = exact successes + failures (including inexact). Quantiles are nearest-rank over exact successes only, null when none; inexact latencies remain separate. Achieved ops/s = exact successes / measured client-window seconds. Target CPU microseconds/op = raw resource-window CPU delta / started operations, explicitly labelled started, null for zero. Retain raw denominators and both window intervals for recomputation. Global clear publishes an individual sample. Extend planning, wrapper dispatch and admission for 96 native and 48 MCP API chunks (three repetitions, four fills), preserving rotations and cost chunks. Publish nonlaunchable rows without invented receipts. Admission rejects missing/duplicate coordinates and tampered counts/statistics/resource evidence. B leaves C/D unresolved and cannot claim full v4 freeze/collection.
10. **Proof.** Deterministic tests cover exactness, paging, fidelity/extractor parity, scope preservation, counts/deadlines, null statistics and admission. Ignored real native and bridged MCP proofs use pinned targets and enforced resources, meaningful destructive operations and concurrent bridged requests. Fail without bytes/delegation; run individually under timeout 600 taskset -c 0-31 with load recorded before/after. All gates in [house rules](../../docs/house-rules.md#gates--part-of-every-change), locked root/eval commands, exact coverage/selftest, publish/seal proofs, recipe compilation, license/native-tls proof and decision inventory remain implementation requirements. This design claims no benchmark result or implementation-gate success.

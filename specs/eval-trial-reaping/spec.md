# Reap trial processes after an eval test interrupts their owner

Part of #408. Three green host runs left a newsletter fixture and its mail server holding a gate descriptor for hours. The paid-baseline resume test exercises the failure mode in which a worker dies while its real servers are live. The test that causes this interruption must take responsibility for those processes before acting as the operator who confirms cleanup.

This enforces existing contracts. A worker owns cleanup on handled exits. Forced death can release admission while descendants survive. Resume requires completed cleanup evidence or explicit confirmation after inspection of descendants and private state. [Sequential trials](../../docs/decisions/0076-sequential-eval-trials.md) · [Paid baseline](../../docs/decisions/0137-paid-baseline.md)

## Acceptance Criteria

1. The implementation ledger identifies the exact leaking test and lifecycle boundary from separate baseline and paid_baseline runs and an isolated named test against the candidate. Record the live identities, command roles and trial cwd before rescue. An empty temporary directory alone is insufficient attribution.
2. In the coordinator-death scenario, a competing confirmed resume still refuses while the worker holds admission. Release the hold, let the worker finish its owned cleanup, and observe its family's exit before successful confirmation. Preserve committed score bytes and existing slot-count assertions.
3. In the worker-death scenario, observe the held worker and both live servers before killing it. Preserve the open attempt, the refusal without confirmation for the same attempt ID and its zero additional launches. Before confirmed resume, stop surviving owned descendants, verify cessation, inspect and clear the abandoned private scratch, and preserve the retained partial attempt. Resume continues under the existing scoring, row, CLI and evidence contracts.
4. The affected trial-starting baseline tests check for live owned serve and fixture processes at completion, including after reparenting. Missing ownership evidence fails the check. A survivor is reported with role, identity and cwd before emergency cleanup. All cleanup targets belong to this invocation. Reap direct children and observe terminal state or exit for nonchildren.
5. With only the worker-death cleanup action disabled, the same named test fails at the survivor check and identifies the leaked service and fixture. Emergency cleanup ends them even on this failing run. Restoring the action makes that test pass. Record commands, outcomes and measured added wall time. New checks add at most a few seconds total on the passing path and synchronize on observed events with bounded waits.
6. Record before/after process listings around the full locked Linux eval suite with the candidate binary. No live service or fixture attributable to the suite survives. Run all house gates and verify macOS compilation and applicable suite execution through CI. Exercise the existing offline controls and stand-ins over loopback.
